## 1. 概述

- 单页个人作品集网站，定位：专注计算机科学和 AI 的高中生开发者
- 网站就是 Unit 3 Step 03 定稿 Copy Deck 的"网页外壳"
- 服务于大学申请：让招生官快速、可信地了解项目、兴趣和领导经历

## 2. 要解决的问题

- 招生官看每份申请的时间很短
- 空泛、像 AI 写的自我介绍很容易被认出来
- 作品分散在 GitHub、Vercel 和学校活动里：
  - 一个 AI 工具（AP Question Generator）
  - 一个社团网站（Key Club Website）
  - 几个游戏项目
  - Schoolhouse.world 辅导经历
  - 联合创办的 Key Club
- 目前没有一个地方能用自己的语气，把这些内容连同证据整合起来

## 3. 目标与非目标

### 目标
- **G1**：把 Copy Deck 全部定稿内容（Block A、B、C、D）发布到公开网址
- **G2**：读者 30 秒内明白 Benjamin 是谁、做什么
- **G3**：每条说法都有证据，要么是能打开的链接，要么是具体数字
- **G4**：满足讲义提交前检查清单和 TILT 评分标准
- **G5**：网站代码本身也是一件可信的作品（仓库整洁、技术栈现代）

### 非目标
- 不做内容管理系统（CMS）、登录、后台
- 不做后端、数据库、联系表单（用 mailto 邮件链接）
- v1 不做 Blog
- 不做多语言（only english）

## 4. 目标用户

- **大学招生官**（主要用户）
  - 需要快速、好浏览的概览
  - 需要真实的语气
  - 需要能体现深度的证据
- **老师 / 作业评分人**
  - 所有要求的 Block 都在
  - 零禁用词，有具体数字
- **同学、导师、实习联系人**
  - 项目链接、GitHub、联系方式

## 5. 成功指标

- Copy Deck Block 发布数：4/4（A、B、C、D）
- 网站上的禁用词：0 个
- 每个项目和每段领导经历至少 1 处数字或链接
- Lighthouse 性能 / 无障碍 / SEO：每项 ≥ 90
- 375px 手机宽度下不出现横向滚动
- 作业评分：50/50

## 6. 用户故事

- 作为**招生官**，一打开就看到姓名、方向和简介，不用滚动就知道这是谁
- 作为**招生官**，点开项目能看到真实、能运行的成果，所以相信这些说法
- 作为**招生官**，领导经历有具体数字，能判断影响力
- 作为**评分人**，每个 Copy Deck Block 都清楚呈现，方便对照评分标准
- 作为**手机访问者**，小屏幕上也好读
- 作为 **Benjamin**，只改一个文件就能更新文字，不用碰布局代码

## 10. UI 与视觉设计

### 10.1 通用 UI 规范（无论选哪个方案都适用）
- **布局**
  - 内容区最大宽度约 720–1100px，居中
  - 区块之间上下留白约 96–128px（手机上约 64px）
  - 断点：手机 < 640px · 平板 640–1024px · 电脑 > 1024px
- **间距**：统一用 4 或 8 的倍数（8 / 16 / 24 / 32 / 48 / 64）
- **圆角**：统一一个值（例如卡片 12px、按钮 8px、标签 999px 全圆）
- **字号层级**
  - h1 姓名：48–72px
  - h2 区块标题：28–36px
  - h3 卡片标题：18–22px
  - 正文：16–18px，行高 1.6
  - 标签和说明文字：12–14px
- **颜色**
  - 每个方案都定义浅色和深色两套
  - 只用 1 个强调色，避免花哨
  - 颜色写成变量（design tokens），方便整体换肤
- **图标**：Lucide 或 Simple Icons（技术 logo），线条风格统一
- **动效**
  - 时长 150–300ms
  - 只用于悬停、切换、进入屏幕
  - 开启「减少动态效果」时关闭动画

### 10.2 美术素材清单
- 个人照片或头像（可选；也可以用插画头像或姓名缩写）
- 每个项目 1 张截图（16:9，WebP）
- 网站图标 favicon（「BZ」字母标）
- 社交分享预览图（1200×630，姓名 + 副标题）
- 技术栈图标

### 10.3 视觉方案（可选多个，挑一个或混搭）

#### 方案 A：极简开发者 Minimal Dev
- **关键词**：干净、克制、专业
- **参考感觉**：Vercel、Linear、很多工程师的个人主页
- **配色**
  - 浅色：背景 `#FAFAFA`，文字 `#111111`，次要文字 `#666666`，强调色 `#2563EB`（蓝）
  - 深色：背景 `#0A0A0A`，文字 `#EDEDED`，次要文字 `#A1A1A1`，强调色 `#60A5FA`
- **字体**：正文和标题用 Inter 或 Geist；标签和代码用 JetBrains Mono
- **布局**：单列居中，左对齐文字，大量留白
- **组件**：细边框卡片（1px），悬停时边框变深、轻微上浮
- **动效**：几乎没有，只有悬停反馈
- **优点**：最稳妥，永远不会过时，文字最突出
- **风险**：比较常见，个性不够强

#### 方案 B：终端 / 代码风 Terminal
- **关键词**：极客、命令行、有趣
- **参考感觉**：代码编辑器、终端窗口
- **配色**
  - 只做深色为主：背景 `#0D1117`，文字 `#C9D1D9`，强调色 `#3FB950`（终端绿）或 `#F0B429`（琥珀）
  - 浅色备用：背景 `#F6F8FA`，文字 `#24292F`，强调色 `#1A7F37`
- **字体**：全站用等宽字体 JetBrains Mono 或 IBM Plex Mono
- **布局**
  - Hero 做成终端窗口（顶部三个小圆点），姓名用「打字机」效果逐字出现
  - 区块标题写成命令形式，例如 `$ cat about.md`、`$ ls projects/`
- **组件**：项目卡片像文件列表，技能标签像代码注释 `// React`
- **动效**：打字机效果、光标闪烁
- **优点**：一眼就能看出是写代码的人，令人印象深刻
- **风险**：全等宽字体读长段落比较累；不能做过头

#### 方案 C：杂志编辑风 Editorial
- **关键词**：成熟、有文学感、讲故事
- **参考感觉**：杂志排版、个人随笔网站
- **配色**
  - 浅色：背景 `#F7F4EE`（暖米白），文字 `#1C1917`，强调色 `#C2410C`（砖红）
  - 深色：背景 `#1A1714`，文字 `#F5F0E8`，强调色 `#FB923C`
- **字体**：标题用衬线字体 Fraunces 或 Instrument Serif；正文用 Inter
- **布局**
  - 大号衬线姓名，像杂志封面
  - About 用首字下沉，像文章开头
  - 项目编号 01/02/03 做得很大，像章节号
- **组件**：没有卡片边框，用细分隔线区分内容
- **动效**：极少
- **优点**：和招生官读文书的习惯契合，About 部分特别出彩
- **风险**：「技术感」较弱，需要靠项目内容来体现

#### 方案 D：Bento 网格 Bento Grid
- **关键词**：现代、模块化、信息密度高
- **参考感觉**：Apple 发布会的产品功能网格
- **配色**
  - 浅色：背景 `#F2F2F7`，卡片 `#FFFFFF`，文字 `#1D1D1F`，强调色 `#7C3AED`（紫）
  - 深色：背景 `#000000`，卡片 `#1C1C1E`，文字 `#F5F5F7`，强调色 `#A78BFA`
- **字体**：Inter 或 SF Pro 风格的无衬线字体，标题加粗
- **布局**
  - 首屏就是一个大小不一的卡片网格：姓名卡、简介卡、头像卡、「正在做」卡、技术栈卡、GitHub 卡……
  - 往下是项目和领导经历，也用网格卡片
  - 手机上自动变成单列
- **组件**：大圆角卡片（20–24px），悬停时轻微放大
- **动效**：卡片依次淡入
- **优点**：信息一屏看全，视觉冲击强，很「现代」
- **风险**：长段落（About）放进格子里不好读，需要单独的区块

#### 方案 E：像素游戏风 Pixel / Playful
- **关键词**：好玩、有个性、呼应游戏开发
- **参考感觉**：复古游戏界面、像素艺术
- **配色**
  - 浅色：背景 `#FFF8E7`，文字 `#2B2B2B`，强调色 `#FF5A5F`（红）+ `#00A6A6`（青）
  - 深色：背景 `#1B1B2F`，文字 `#F4F4F4`，强调色 `#FFD166`（金）+ `#06D6A0`（绿）
- **字体**：标题少量用像素字体（Press Start 2P 或 Silkscreen）；正文必须用普通无衬线字体保证可读
- **布局**
  - 项目卡片像游戏关卡选择（Level 01 / 02 / 03）
  - 技能标签像游戏道具
  - 领导经历可以写成「成就解锁 🏆」
- **组件**：硬阴影（偏移的实色阴影，没有模糊）、粗边框
- **动效**：按钮按下时有「按键」位移感，悬停时像素小动画
- **优点**：最有个性，让人记住；直接呼应游戏开发项目
- **风险**：太「玩」会显得不够严肃；建议只用在点缀上，作为申请网站要控制分寸

#### 方案 F：深色渐变 Gradient Dark
- **关键词**：科技、AI 感、炫
- **参考感觉**：AI 产品官网
- **配色**
  - 深色为主：背景 `#09090B`，文字 `#FAFAFA`，渐变 `#6366F1 → #EC4899`（靛蓝到粉）
  - 浅色备用：背景 `#FFFFFF`，文字 `#09090B`，同样的渐变用作点缀
- **字体**：Geist 或 Space Grotesk
- **布局**
  - Hero 背后放模糊的渐变光斑
  - 姓名或副标题用渐变文字
  - 卡片半透明加毛玻璃效果
- **组件**：发光边框，悬停时光晕跟随鼠标
- **动效**：背景光斑缓慢流动
- **优点**：契合 AI 方向，视觉上最抢眼
- **风险**：这种风格现在很多「AI 模板网站」都在用，容易显得不够原创，和「Anti-Slop」主题有点冲突；性能开销也更大

#### 混搭建议
- **A + B**：整体极简，只在 Hero 用一个终端窗口、区块标题用等宽字体 → 专业又有极客味（**推荐**）
- **C + A**：About 用杂志排版讲故事，项目区用极简卡片 → 适合想突出文书感的方向
- **D + A**：首屏用 Bento 网格吸引眼球，下面的内容回到极简单列 → 现代感最强
- **A + E**：整体极简，只在游戏项目卡片和「成就」上用像素元素 → 个性点到为止

### 10.4 Hero 布局备选
- **H1 居左文字**：姓名、副标题、简介、按钮全部左对齐，右侧留白
- **H2 左文右图**：左边文字，右边头像或插画
- **H3 居中**：全部居中，简洁有仪式感
- **H4 终端窗口**：文字放在一个仿终端窗口里，逐行打出
- **H5 Bento**：首屏直接是卡片网格

### 10.5 项目卡片备选
- **P1 纯文字卡**：编号 + 标题 + 描述 + 标签，最简洁
- **P2 截图卡**：顶部截图，下面是文字
- **P3 横向长条**：左边截图，右边文字，一个项目占一行
- **P4 列表行**：像文件列表一样的一行，悬停时展开描述
- **P5 大编号章节**：巨大的 01/02/03 + 文字，杂志感

  - 能展示的技术能力更少

## 14. 风险

- **缺少真实数字，文字变空泛** → Phase 1 用 Socratic 方式一次问一个问题

- **范围不断扩大** → 坚持 v1 范围，额外功能放到 v2/v3
